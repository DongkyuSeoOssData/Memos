# Memos 메모 다루기

Memos 앱은 메모 하나를 메모 폴더의 `{id}.json` 파일 하나로 저장한다. 이 스킬은 `scripts/memos.py`(파이썬 표준 라이브러리만 씀)로 그 파일들을 앱과 같은 규칙으로 읽고 쓴다. 파일을 직접 열어 고치지 말고 항상 이 스크립트를 쓴다. 이전 내용 기록, 휴지통, 동기화 삭제 대기열, 수정일시를 스크립트가 앱과 똑같이 처리해 주기 때문이다.

## 실행

```bash
python "<이 스킬 폴더>/scripts/memos.py" <명령> [옵션]
```

- 메모 폴더는 `~/.memoit_custom/settings.json`의 `local_memo_path`를 따르고, 없으면 `~/.memoit_custom/memos`를 쓴다. 처음에는 `info`로 위치와 개수를 확인한다.
- 환경 변수 `MEMOS_HOME`(설정 폴더), `MEMOS_DIR`(메모 폴더)로 바꿀 수 있다. 시험할 때는 꼭 임시 폴더를 가리키게 한다.
- 메모는 사용자 PC에 있다. 메모 폴더가 없다고 나오면(예: 클라우드 세션) 지어내지 말고, 메모가 이 컴퓨터에 없다고 알린다.
- 메모를 고르는 인자 `<memo>`에는 id, id 앞부분(4자 이상), 정확한 제목, 제목 일부를 쓸 수 있다. 여러 개가 맞으면 후보를 보여 주며 실패하니, id로 다시 지정한다.

## 명령

| 하고 싶은 일 | 명령 |
|---|---|
| 위치·개수 확인 | `info` |
| 목록 | `list [--folder 업무] [--tag 마트] [--fav] [--todo] [--limit 30] [--json]` |
| 검색 (제목·본문) | `search "검색어" [--json]` |
| 하나 보기 | `show <memo> [--json]` |
| 새 메모 | `new --title "제목" [--folder 업무/A] [--code Python] [--color yellow] [--fav] --text "본문"` |
| 끝에 덧붙이기 | `append <memo> --text "내용"` (`--todo`: 줄마다 ☐ 붙여 할 일로) |
| 본문 통째로 바꾸기 | `write <memo> --file 새본문.txt` |
| 일부 글자 바꾸기 | `replace <memo> "옛 글" "새 글" [--all]` |
| 체크 항목 | `check <memo> 2 "계란" [--state on\|off\|toggle]` (번호는 1부터, 또는 항목 글자 일부) |
| 속성 바꾸기 | `set <memo> [--title ..] [--folder ..] [--fav on\|off] [--protect on\|off] [--color ..]` |
| 알림 | `remind <memo> --at "2026-11-20 09:00"` / `--at 15:30` / `--at +30m` |
| 반복 알림 | `remind <memo> --repeat daily\|weekdays --at 09:00`, `--repeat weekly --weekdays 0,2 --at 09:00`, `--repeat monthly --days 1,15 --at 09:00`, `--repeat cron --cron "0 9 * * 1-5"` |
| 알림 풀기 / 목록 | `remind <memo> --off` / `reminders` |
| 폴더·태그 현황 | `folders` / `tags` |
| 지우기 / 되살리기 | `trash <memo>` / `restore <memo>` / `trash-list` |
| 이전 내용 | `history <memo>` / `history <memo> --index 3` |

- 여러 줄 본문은 `--text`에 넣기보다 임시 파일에 써서 `--file`로 넘기거나 표준 입력으로 넘긴다. (따옴표·줄바꿈이 셸에서 깨지지 않게)
- 사람이 읽을 결과는 기본 출력으로 충분하다. 결과를 가공해야 하면 `--json`을 쓴다.
- 목록 표시: ★ 즐겨찾기, 🔒 암호 메모, ⏰ 알림, 🛡 삭제 방지, 👁 앱 화면에 열려 있음, `[SQL]` 코드 메모, `☐ 2/5` 체크리스트 진행.

## 메모 앱의 규칙 (꼭 지킨다)

- **체크리스트**는 줄 맨 앞의 `☐`(할 일) / `☑`(끝냄) 글자다. 할 일을 적을 때는 이 글자를 쓴다. `- [ ]` 같은 마크다운은 앱에서 체크 상자로 보이지 않는다.
- **폴더**는 실제 디렉터리가 아니라 메모의 `folder` 값이다. `업무/프로젝트A`처럼 `/`로 하위 폴더를 만든다. 빈 값은 미분류다.
- **해시태그**는 본문의 `#단어`다. 태그를 붙여 달라면 본문에 `#태그`를 적는다.
- **암호 메모**(🔒)의 본문은 암호문이라 읽거나 고칠 수 없다. 제목·폴더·즐겨찾기만 바꿀 수 있다. 내용이 필요하면 사용자에게 앱에서 열어 달라고 한다.
- **서식 메모**(굵게·색 등을 써서 HTML로 저장된 메모)는 읽기와 체크 항목 켜고 끄기만 한다. `append`·`write`·`replace`는 서식을 깨뜨리므로 막혀 있다. 사용자가 서식을 버려도 된다고 분명히 말한 경우에만 `write --plain`을 쓴다.
- **삭제 방지**(🛡)가 걸린 메모는 `trash`가 거부한다. 사용자가 원할 때만 `set --protect off` 후에 지운다.
- 본문·제목을 바꾸면 바뀌기 전 내용이 '이전 내용'에 남는다(메모마다 최근 20개). 실수했으면 `history`로 찾아 `write`로 되돌린다.
- 알림은 그 PC에서만 울리는 값이라 다른 기기로 동기화되지 않는다.

## 앱이 켜져 있을 때

- 앱은 메모 파일의 변경을 실시간으로 감시하지 않는다. 새로 만든 메모와 바뀐 목록은 메모 탐색기를 다시 열면 보인다.
- **👁 앱 화면에 열려 있는 메모**는 앱이 자기 사본을 들고 있어서, 사용자가 그 창을 옮기거나 고치면 그 사본으로 파일을 다시 써서 바깥에서 고친 내용이 사라질 수 있다. 열려 있는 메모의 본문을 고치기 전에는 사용자에게 그 메모 창을 먼저 닫아 달라고 하거나, 고친 뒤 앱을 다시 켜 달라고 알린다.
- 구글 드라이브 동기화를 쓰는 경우, 바깥에서 고친 메모는 앱을 다시 켜거나 수동으로 동기화할 때 드라이브로 올라간다. 지운 메모는 삭제 대기열에 넣어 두므로 다음 동기화 때 드라이브에서도 지워진다.

## 일하는 방식

1. 대상 메모가 확실하지 않으면 먼저 `search`나 `list`로 찾고, 후보가 여럿이면 사용자에게 어느 것인지 묻는다.
2. 고치기 전에 `show`로 지금 내용을 확인한다. 특히 `write`(통째로 바꾸기)는 기존 내용을 바탕으로 새 본문을 만든다.
3. 지우기(`trash`)와 통째로 바꾸기(`write`)는 사용자가 그렇게 해 달라고 한 경우에만 한다. 덧붙이기로 충분하면 `append`를 쓴다.
4. 끝나면 무엇을 바꿨는지(메모 제목, 바뀐 부분)를 짧게 알린다.
